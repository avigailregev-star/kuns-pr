# עיצוב: שיעורים קבועים (קבוצות תיאוריה/הרכב) — ניהול מראש, שיבוץ בבחירה בלבד

**תאריך:** 2026-07-23
**פרויקט:** קונסרבטוריון — מערכת הרשמה

---

## הבעיה

כיום קבוצה (`groups` + `group_schedules`) נוצרת רק "תוך כדי" שיבוץ תלמיד/ה ספציפי/ת: לוחצים "+ הרכב"/"+ תיאוריה" בשורת התלמיד/ה, ואם אין קבוצה מתאימה — "➕ צור שיעור חדש" רק קובע את `selected_course` על הרישום, בלי מורה/יום/שעה. הקבוצה בפועל מקבלת מורה/יום/שעה רק דרך מסלול ישן ונפרד (`AssignmentPanel`, מסך שיבוץ השיעור הפרטני), שדורש לבחור כבר תלמידים לפני היצירה.

התוצאה: אי אפשר "לבנות" קבוצה קבועה (מורה+יום+שעה) מראש, בלי תלות בתלמיד/ה ראשון/ה קונקרטי/ת. וגם: "תיאוריה" היום היא סוג שיעור יחיד וקבוע (`תיאוריה`), בלי אפשרות להבדיל בין כמה מסגרות שונות (פיתוח קשב, קצב לכולם, קומפוזיציה וכו').

המטרה: לאפשר להגדיר מראש רשימת "שיעורים קבועים" (קבוצות עם מורה+יום+שעה) לכל סוג (תיאוריה על תת-סוגיה, הרכב), במקום נפרד מטבלת התלמידים — ולאחר מכן, בשורת כל תלמיד/ה, "+ תיאוריה"/"+ הרכב" יהיו **בחירה בלבד** מתוך הרשימה הקיימת, בלי יצירה.

## מחוץ לסקופ

- שיעורי נגינה פרטניים (השורה הרגילה של שיבוץ תלמיד/ה — בחירת מורה/יום/שעה על הרישום הפרטני עצמו, במסך שיבוץ) — **ללא שינוי כלשהו**, ממשיכים במסלול הקיים לגמרי.
- שינוי שם קבוצה לאחר יצירתה (מספור אוטומטי בלבד כרגע; שינוי שם ידני יתאפשר בעתיד, לא כאן).
- מסך/טאב חדש ייעודי ל"קבוצות" — הניהול נכנס לתוך טאב "מורים" הקיים.
- הגבלת מספר תלמידים בקבוצה (capacity) — לא נדרש.
- כל שינוי בסנכרון לאפליקציית הנוכחות (`syncToAttendance.js`) — משתמשים במנגנון הקיים כמו שהוא.

## הפתרון

### 1. `lib/groupNaming.js` — סוגי שיעור קבוע חדשים ומספור אוטומטי

מוסיפים ל-`LESSON_TYPE_OPTIONS`:

```js
{ label: 'פיתוח קשב', value: 'theory' },
{ label: 'קצב לכולם', value: 'theory' },
{ label: 'קומפוזיציה', value: 'theory' },
```

("תיאוריה" ו"תזמורת כלי קשת" כבר קיימים ברשימה; שלושת אלה מצטרפים תחת "+ תיאוריה" יחד עם "תיאוריה" הקיים.)

מוסיפים `THEORY_LABELS` (אנלוגי ל-`ENSEMBLE_LABELS` הקיים):

```js
export const THEORY_LABELS = LESSON_TYPE_OPTIONS
  .filter(o => o.value === 'theory')
  .map(o => o.label);
```

מוסיפים פונקציית מספור אוטומטי, לשימוש רק בזרימת היצירה החדשה (טאב מורים):

```js
export function nextNumberedGroupName(label, existingGroupNames) {
  const re = new RegExp(`^${escapeRegExp(label)} (\\d+)$`);
  let max = 0;
  for (const name of existingGroupNames) {
    const m = re.exec(name);
    if (m) max = Math.max(max, Number(m[1]));
  }
  return `${label} ${max + 1}`;
}
```

ופונקציית התאמה מקבילה ל-`matchesLessonType` הקיים (ששומר על מוסכמת ה-" - " הישנה ולא מתאים למוסכמת המספור החדשה):

```js
export function matchesGroupLabel(groupName, label) {
  return groupName === label || new RegExp(`^${escapeRegExp(label)} \\d+$`).test(groupName);
}
```

`computeGroupName`/`matchesLessonType` הקיימים נשארים ללא שינוי — עדיין משמשים את המסלול הישן (`AssignmentPanel`/`handleCreateGroup`), שלא נוגעים בו.

### 2. טאב "מורים" (`components/TeachersTab.jsx`) — ניהול השיעורים הקבועים

בכרטיס של כל מורה (`TeacherCard`), אזור חדש "שיעורים קבועים", לצד האזור הקיים של תלמידים משובצים:

- **רשימת השיעורים הקיימים** של אותה מורה: `groups.filter(g => g.teacher_id === t.id)`, כל שורה מציגה שם קבוצה, יום+שעה (מ-`group_schedules`), ומספר תלמידים משובצים (`registrations.filter(r => r.group_id === g.id).length`). כפתור מחיקה (מחזור-שימוש ב-`DELETE /api/groups` הקיים) — פעיל תמיד; אם יש תלמידים משובצים, מוצג אישור (`confirm`) שמזכיר שהם יוסרו גם הם (כמו היום ב-`AssignmentPanel`).
- **הוספת שיעור קבוע חדש:**
  1. דרופדאון סוג — כל `LESSON_TYPE_OPTIONS` שה-`value` שלהם הוא `theory`/`orchestra`/`choir` (לא `individual_45`/`individual_60`/`elite_duet`/`melodies_individual`).
  2. כפתורי יום, מתוך `t.teacher_availability_ranges` (כמו ב-`AssignmentPanel`).
  3. שדה שעה (`<input type="time">`), מוזן מראש מ-`start_time` של הטווח שנבחר.
  4. כפתור "שמור" — קורא ל-`POST /api/groups` עם:
     ```js
     {
       name: nextNumberedGroupName(label, allGroups.map(g => g.name)),
       lesson_type: getLessonTypeValue(label),
       teacher_id: t.id,
       assigned_day,
       assigned_time,
     }
     ```
     המספור הוא **גלובלי לתווית**, לא לפי מורה — כלומר `allGroups` הוא כל הקבוצות במערכת, לא רק של המורה הנוכחית (כך ש"פיתוח קשב 1" אצל מורה אחת ו"פיתוח קשב 2" אצל מורה אחרת, לדוגמה, לא מתנגשים ולא מתאפסים). (בלי `student_registration_ids` — נשאר ריק, כפי שה-endpoint כבר תומך בו.) בהצלחה — מוסיפים לרשימת הקבוצות המקומית ומאפסים את הטופס. שגיאת חפיפה (409 מה-endpoint הקיים) מוצגת ב-`alert`, כמו בכל מקום אחר במערכת.

התלות היחידה החדשה ב-`TeachersTab.jsx`: הבאת רשימת `groups` המלאה (כבר מובאת היום כ-`groupsById`; מוסיפים גם מערך `groups` רגיל מאותה תשובת `/api/groups`).

### 3. `components/AdminTable.jsx` — "+ תיאוריה"/"+ הרכב" הופכים לבחירה בלבד

- **דרופדאון סוג** נוסף לפני רשימת הקבוצות התואמות: `THEORY_LABELS` (לכפתור "+ תיאוריה") או `ENSEMBLE_LABELS` (לכפתור "+ הרכב"). `addonPickerFor` מקבל שדה `label` נוסף (`{ rowId, kind, label }`), מתאפס בכל פתיחה מחדש.
- **רשימת הקבוצות התואמות** מסוננת גם לפי `lesson_type` (כמו היום) וגם לפי ההתאמה המדויקת לתווית שנבחרה: `groups.filter(g => wantedTypes.includes(g.lesson_type) && matchesGroupLabel(g.name, label))`.
- **מוסר לחלוטין** ה"➕ צור שיעור חדש" מתוך תת-הפאנל הזה (גם עבור תיאוריה וגם עבור הרכב) — כולל ה-`<select>` של `addonNewLabel` והכפתור "צור". אם `matching.length === 0`, מוצג רק "אין קבוצות קיימות מסוג זה — יש להוסיף שיעור קבוע בטאב מורים" (הודעה מכוונת, לא פעולה).
- לחיצה על אחת הקבוצות ברשימה ממשיכה לקרוא ל-`handleAddAddon(contactRow, { groupId: g.id })` בדיוק כמו היום — ללא שינוי בהתנהגות השיבוץ עצמה.

### 4. `app/api/registrations/addon/route.js` — פישוט + בדיקת כפילות לפי תווית ולא לפי קטגוריה

- מסירים לחלוטין את מסלול `newLabel` (יצירת רישום בלי קבוצה) — הוא כבר לא נקרא משום מקום אחרי השינוי ב-AdminTable. הבקשה מחייבת `groupId` תמיד; חסרונו מחזיר `400`.
- בדיקת הכפילות (חוסמת הוספה כפולה) עוברת מרמת **קטגוריה** ("יש כבר תיאוריה פעילה כלשהי") לרמת **תווית ספציפית** ("יש כבר `פיתוח קשב` פעיל") — כדי לאפשר לתלמיד/ה להיות משובץ/ת בו-זמנית לכמה סוגים שונים (למשל גם `קצב לכולם` וגם `קומפוזיציה`), אך לא פעמיים לאותו סוג עצמו. הבדיקה: `matchesGroupLabel(existingReg.selected_course, group.name-base-label)` — בפועל, מספיק להשוות אם `getLessonTypeValue` זהה **וגם** `matchesGroupLabel` מול אותה תווית בסיס (למשל, שולפים את התווית מתוך `group.name` בעזרת הסרת הסיומת המספרית, או פשוט מעבירים את ה-`label` שנבחר בפאנל כפרמטר נוסף לבקשה כדי לא לגזור אותו מחדש בשרת).
  - שינוי חתימת הבקשה: `{ sourceId, groupId }` — התווית לבדיקת הכפילות נגזרת בשרת מ-`group.name` (מסירים סיומת `" \d+$"` אם יש), לא נדרש פרמטר נוסף מהלקוח.
- שאר ההתנהגות (העתקת פרטי הורה/תלמיד, `linked_registration_id`, מילוי מורה/יום/שעה מלוח הזמנים של הקבוצה, יצירת רשומת `students`) — ללא שינוי.

### 5. אין שינויי סכמה

הפתרון כולו משתמש בטבלאות הקיימות (`groups`, `group_schedules`, `students`, `registrations.group_id`/`linked_registration_id`).

## דוגמה מלאה

1. **בטאב מורים**, בכרטיס של המורה נועה, לוחצים "שיעורים קבועים" → "הוסף שיעור קבוע". בוחרים סוג "פיתוח קשב", יום שלישי, שעה 16:00 → "שמור". נוצרת קבוצה "פיתוח קשב 1", מורה=נועה, יום=שלישי, שעה=16:00, בלי תלמידים.
2. עוד קבוצה: סוג "פיתוח קשב", יום חמישי, שעה 15:00, מורה אחרת (רותם) → "שמור" → נוצרת "פיתוח קשב 2".
3. **בטבלת התלמידים**, פותחים את שורת דני, לוחצים "+ תיאוריה" → דרופדאון: "תיאוריה" / "פיתוח קשב" / "קצב לכולם" / "קומפוזיציה". בוחרים "פיתוח קשב" → מופיעה רשימה: "פיתוח קשב 1 · נועה · יום שלישי 16:00", "פיתוח קשב 2 · רותם · יום חמישי 15:00" → בוחרים אחת → דני משובץ מיידית, עם מורה/יום/שעה שהועתקו מהקבוצה.
4. פותחים את שורת דני שוב, לוחצים "+ תיאוריה" → בוחרים "קצב לכולם" (סוג אחר) → מותר, כי הכפילות נבדקת רק מול אותו סוג בדיוק (לא כל "תיאוריה" ככלל).
5. מנסים להוסיף לדני עוד "פיתוח קשב" → נחסם ("לתלמיד/ה כבר יש שיבוץ פעיל מסוג זה").

## קבצים מושפעים

- **`lib/groupNaming.js`:** הוספת 3 אפשרויות ל-`LESSON_TYPE_OPTIONS`, הוספת `THEORY_LABELS`, `nextNumberedGroupName`, `matchesGroupLabel`.
- **`components/TeachersTab.jsx`:** אזור "שיעורים קבועים" חדש בכרטיס מורה — רשימה + טופס הוספה + מחיקה. הבאת מערך `groups` מלא (בנוסף ל-`groupsById` הקיים).
- **`components/AdminTable.jsx`:** דרופדאון סוג בפאנל "+ תיאוריה"/"+ הרכב", סינון לפי `matchesGroupLabel`, הסרת "➕ צור שיעור חדש" מתת-הפאנל הזה.
- **`app/api/registrations/addon/route.js`:** הסרת מסלול `newLabel`, שינוי בדיקת הכפילות לרמת תווית (נגזרת מ-`group.name`).
- **`app/api/groups/route.js`:** ללא שינוי — נעשה בו שימוש חוזר כמו שהוא (יצירה בלי `student_registration_ids`).

## מקרי קצה

- **אין שיעורים קבועים כלל מסוג מסוים:** הרשימה ריקה, מוצגת הודעה שמפנה לטאב מורים — אין פעולת יצירה מהמקום הזה.
- **תלמיד/ה עם שיבוץ פעיל מאותו סוג בדיוק:** הבחירה מהרשימה נחסמת בשרת (409), עם הודעה שמזכירה את הסוג הספציפי.
- **תלמיד/ה עם שיבוצים בכמה סוגים שונים (למשל גם פיתוח קשב וגם קומפוזיציה):** מותר לגמרי, ללא הגבלת כמות סוגים שונים.
- **מחיקת שיעור קבוע שיש בו תלמידים מטאב מורים:** מחזור-שימוש בהתנהגות המחיקה הקיימת של `DELETE /api/groups` (מנקה `group_id` מהרישומים, מוחק שורות `students`), עם אישור (`confirm`) לפני הפעולה.
- **חפיפת שעות בין שיעור קבוע חדש לשיעור קיים של אותה מורה:** נחסם על ידי הבדיקה הקיימת ב-`POST /api/groups` (409), ללא שינוי.
