# עדכון ניהול הרישומים

## התנהגות

- הכיתוב ״חדש״ מוצג כ״טרם שובץ״ בלי לשנות את הערך השמור. מצבי ביניים נשמרים ומוצגים לצד ״טרם שובץ״.
- תשלום ממתין מוצג כ״טרם שולם״.
- מלבן שיעור עם שיבוץ או תשלום חסר מקבל רקע אדום, גם בהרכב ובתיאוריה. רישום מבוטל אינו מוצג כחוב חדש.
- בהיעדר הרכב או תיאוריה אפשר לסמן ״לא נדרש״ בפרטי התלמידה. הסימון נשמר בנפרד, ואינו מוחק שיעורים קיימים.
- ״טופל״ כולל תלמידים שכל רישומיהם שובצו ושולמו, וכל אחד מהתחומים הרכב ותיאוריה קיים או סומן כלא נדרש.
- כל יתר התלמידים נשארים ב״רישומים״, כולל מי ששובץ וטרם שילם. שינוי שמבטל השלמה מחזיר את התלמיד לרישומים.

## התקנה באתר הפעיל

1. לפני שינוי במסד הפעיל, ליצור גיבוי מסד נתונים ולוודא את דרך השחזור. הגיבוי המקומי בתיקיית `.backups/2026-09-08-registration-workflow` הוא גיבוי קוד בלבד.
2. להריץ בעורך SQL של פרויקט Supabase את `migrations/2026-09-08-registration-requirements.sql`. הקובץ מוסיף רק שתי עמודות ואינו מוחק או משנה ערכים קיימים. אין צורך להריץ את כל קובץ הסכמה.
3. לפרסם את גרסת הקוד החדשה ולבדוק ברישום בדיקה את שמירת הסימונים לאחר רענון, ואת המעבר בין שתי הלשוניות.

ללא המיגרציה סימוני ״לא נדרש״ לא יישמרו; תוצג שגיאה במקום אישור שמירה שגוי. הקוד הישן יכול לפעול גם כשהעמודות החדשות קיימות, ולכן חזרה לגרסת קוד קודמת אינה דורשת מחיקת נתונים או עמודות.
